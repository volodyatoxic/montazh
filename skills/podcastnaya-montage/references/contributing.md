# Как дообучать скилл

Скилл общий для всей команды. Монтажёры улучшают его через своих агентов, владелец репозитория проверяет и принимает правки, и при следующем запуске они приезжают ко всем.

```
монтажёр: «запомни это в скилл»  →  агент правит клон и открывает PR  →  владелец (с агентом) разбирает
→  merge в main  →  у всех скилл сам обновляется при старте
```

## Что отправлять

- Общие правила монтажа, в которых монтажёр поправил агента: «мы так не режем», «плашку ставим так».
- Грабли DaVinci Resolve, ATEM, Zoom P8 и способ их обойти.
- Исправления скриптов и новые скрипты.
- Новые слова и случаи для сносок — `rules/publish-risks.json`.

## Что не отправлять

- **Ничего про студию и клиентов:** название студии, имена гостей и клиентов, темы выпусков, профили, пути к дискам с именами. Репозиторий публичный. Про клиента пиши в `_agent/` его проекта. Пример из съёмки — обезличь: «подкаст на 4 камеры, гость с тихим голосом».
- Медиа, расшифровки, базы `_agent/`, кадры. `tools/check.py` их не пропустит.
- Вкус одного выпуска («тут без общего плана»).
- Изменение железных правил из SKILL.md — только предложением в описании PR, не правкой.

## Порядок — для агента

1. Повод: монтажёр сказал «запомни в скилл / для всех / это общее правило» — или ты сам поймал общие грабли. Сформулируй правку одной фразой и покажи монтажёру. Согласен — правь.
2. Правь прямо в клоне скилла. Папка скилла — `$SKILL` (где SKILL.md), корень репозитория — `git -C "$SKILL" rev-parse --show-toplevel`. Куда что: порядок работы и правила — `SKILL.md`; монтаж — `references/cutting.md`; Resolve — `references/resolve.md`; материал и железо — `references/studio-material.md`; проверка — `references/qa.md`; сдача — `references/delivery.md`; графика — `references/graphics.md`; скрипты — `scripts/`. Дописывай в подходящий раздел, не плоди дубли.
3. В `CHANGELOG.md` скилла — строка под заголовком `## Не выпущено` (создай его сверху, если нет): что и почему. `VERSION` не трогай — версию поднимает владелец при выпуске.
4. Описание PR — во временном файле вне репозитория: что поменял, какой случай к этому привёл, на чём проверено. Без имён клиентов.
5. Отправка: `python3 <репозиторий>/tools/contribute.py "Коротко, что поменял" --body <файл>` (Windows — `py`). Скрипт проверит репозиторий, положит правки на ветку, запушит (в форк, если прав на запись нет) и откроет PR. Ссылку на PR покажи монтажёру.
6. После отправки клон возвращается на `main`, и правка у монтажёра не работает, пока PR не примут. Если она нужна в текущем проекте прямо сейчас, примени её вручную только в этом проекте.

Один PR — одна тема. Статус своих PR: `gh pr list --repo <владелец/имя из git remote get-url origin> --author @me`.

Если ты владелец репозитория (`gh repo view --json viewerPermission` → `ADMIN`): PR не нужен, коммить прямо в `main` и пушь — по тем же правилам.
