# Материал студии: ATEM + P8

## Обычный пайплайн
Сняли на ATEM Mini Pro ISO → камеры берём с ATEM, звук — с Zoom PodTrak P8 → на таймлайне синхронизируем расчётом. Нет P8 — тревога.

## Стандарт раскладки (операторы раскладывают так)
```
<проект>/
  source/CAM …/        ISO-файлы камер ATEM (бывает, все камеры в одной папке CAM 1 — имени папки не верь)
  source/MIC …/        дорожки P8: MIC1.WAV … MIC6.WAV (иногда MIC6 01.WAV, MIC6 02.WAV — части)
  project/Podcast.drp  проект/лог ATEM
  renders/             рендеры для клиента
```
⚠️ Точное дерево сверяем на реальной съёмке и дописываем сюда. Роль файла определяй по имени файла и содержимому, а не по папке.

## ATEM Mini Pro ISO
- Одна запись = ISO-файл на каждый вход (`<Имя> CAM 1 01.mp4`, H.264, AAC), программа (`<Имя> 01.mp4`), WAV источников звука (48 кГц / 24 бит), файл `.drp`.
- Все ISO одной записи имеют общий старт и длину — между собой синхронны. Разная длина = тревога (файл оборван).
- `.drp`: Resolve открывает его как проект с уже расставленной нарезкой оператора (File → Import Project; API `ImportProject`). Скилл сотрудника разбирал его как JSON-строки с `masterTimecode`, `mixEffectBlocks[].source` (переключения) и `upstreamKeys[].onAir` (PiP = метка оператора «здесь проблема»). ⚠️ Какой формат у нашей студии — сверить на реальном файле.
- Метки оператора (PiP): ставятся сразу ПОСЛЕ проблемы, длинные держат всю проблему. Проблема — до начала метки или внутри; смотри расшифровку от `a−25 с` до `b+4 с`. Метка без явного брака — не режь, жёлтый маркер.
- Частый брак: оператор нажал не ту кнопку → вспышка (план < 0,5 с) или строб.

## Zoom PodTrak P8 (мануал, «P8 folder and file structure»)
```
<карта>/2026_1031_1430.WAV                стерео-микс, имя = дата/время старта по часам P8
<карта>/P8_Multitrack/2026_1031_1430/     MIC1…MIC6.WAV (моно), PHONE.WAV, SOUND_PAD.WAV (стерео), USB.WAV
<карта>/P8_Settings/*.ZWV, P8SETTING.ZSF  служебное
```
- WAV 44,1 кГц / 16 бит. В студии Keep Track Files = Original Data: дорожки чистые.
- Без папки дорожек (опция выключена) есть только стерео — спикеров не разделить, тревога.
- После раскладки по стандарту имя дубля с датой теряется → синхра только по звуку.

## Сценарии съёмки (определяет `scan.py`)
| | Что нашли | Что делаем |
|---|---|---|
| S1 | ATEM + P8 с дорожками | стандарт: проект ATEM, звук P8, синхра расчётом |
| S2 | ATEM без P8 | тревога; звук из WAV ATEM или камер |
| S3 | P8 без ATEM | аудиоподкаст или камеры отдельно (S4) |
| S4 | камеры без ATEM + P8 | синхра каждой камеры к P8, переключаем сами по говорящему |
| S5 | OBS, стрим, вебинар | вырезка пауз и сбоев, только жёсткие склейки |
| S6 | прочее | ручной разбор |

## Тревоги (пометить и продолжить)
Звук: нет P8; P8 без дорожек; запись P8 короче камер или началась позже; мик молчит или клипует; синхра ненадёжна (низкий пик корреляции).
Картинка: не хватает файла ATEM (проект ссылается, файла нет или он короче); заморозка, чёрный кадр, пропадание HDMI; нет `.drp`; ISO разной длины.
Заморозку ловим быстро: ключевые кадры (`-skip_frame nokey`) + `freezedetect`/`blackdetect` на уменьшенной картинке, потом точно — только подозрительные места.
Где помечаем: маркер (голубой — картинка, жёлтый — звук), строка в начале отчёта, `alerts.jsonl`.

## Синхра P8 ↔ камеры
- Кросс-корреляция (GCC-PHAT) звука P8 и звука камеры (общий план слышит всех), 16 кГц моно, полоса 150–4000 Гц, окна по 60 с в 8 точках → линейная модель `mic = cam + a + b·cam`.
- Типично a = 0,09–0,25 с, b ≈ ±13 ppm (часы рекордера). За час ≈ 47 мс. Все мики одного P8 дают одни a, b.
- В v00 мик кладётся одним клипом по середине (края ±23 мс на часе — терпимо). Запись длиннее ~60 мин — кусками со своим смещением, стыки в общей тишине. Звук не пересчитываем.
- Каждую часть записи (перезапуск) считаем отдельно.
- **Липсинк: корреляция равняет звук со звуком, а не с губами — после неё нужна вторая поправка.**
  Измерено 30.10.2026 на ATEM Mini Pro ISO 1080p50 (первая боевая съёмка): встроенный звук ATEM **опережает собственную картинку на ~130 мс**. Дорожки P8, выставленные по нему, приходят раньше изображения на те же 130 мс.
  Как мерить: найти в материале хлопок или «дай пять» → кадр касания ладоней на общем плане против атаки в мике. Пример: касание 522,855 с (камера), атака в MIC5 522,8827 с → верное смещение P8 к картинке всего +28 мс, тогда как корреляция давала +138 мс.
  Поправку писать в `00_db/sync.json` как `lipsync_s` и применять во всех сборках. Для этой студии при 50p это **+7 кадров** (остаток +0,38 кадра, звук чуть позже картинки — так лучше на слух, чем чуть раньше).
  Сдвинуть дорожки на готовом таймлайне: `scripts/resolve_resync.py`.
  В курсах студии раньше понадобилась поправка +6 кадров 25p (240 мс) — порядок тот же, величину меряем на каждой съёмке.
- Встроенный AutoSync Resolve дрейф не лечит.

## Хранение (стандарт студии №1)
Две копии материала, монтажёр работает с копией, исходники не переименовывает и не двигает. Клиентский материал хранится 5 дней после сдачи. На exFAT — только ASCII-имена новых файлов.
